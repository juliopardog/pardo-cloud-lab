Notes from the workbench.

Technical context for the lab. Dated incident reports and supporting screenshots will be added when reviewed.

Building a self-hosted runner

A runner receives jobs from GitHub and executes the workflow on its host. Keep its service account separate from routine administration. The supplied lab configuration targets the pardo-deploy label.

Troubleshooting Linux permissions

Investigate file ownership, group membership, and service identity separately. No incident-specific diagnostic transcript has been supplied; verified troubleshooting evidence will be added here.

Deploying Nginx with Docker

Nginx serves built static files. A frontend build should produce an index.html and its assets before deployment. The runner is a host service and is not assumed to be containerized.

Configuring SSH authentication

Keep private keys outside source control. Verify the destination host and use scoped access. Private key material and internal network details are intentionally excluded from public documentation.

Designing CI/CD workflows

Separate checkout, build, deployment, and health verification. Review the actual existing workflow before altering its behavior. A successful deployment test does not prove every future push will deploy.

Improving infrastructure security

Keep administration private, minimize privileges, and expose only sanitized read-only operational data. Authentication secrets belong on a server, never in browser bundles.
